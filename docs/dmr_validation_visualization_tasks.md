# Задача по улучшению визуализации DMR-валидации (формулировка, без решения)

Документ фиксирует требования к переработке визуализации модуля. Это
постановка задачи: что не так сейчас, каким должен стать результат и по каким
критериям приёмки судить. Реализация — отдельным шагом.

## 1. Проблемы текущей визуализации

1. **Легенды.** Часть графиков вовсе без легенды (непонятно, что за серии/цвета); там, где легенда есть, она рисуется внутри осей и **перекрывает данные** (`ax.legend(frameon=False)` без вынесения за пределы области).
2. **Графики не отражают процесс анализа.** Сейчас это набор разрозненных столбчатых диаграмм и боксплотов. Нет визуального нарратива: вход → вызов callers → консенсус → подтверждение (GLM/GLMM) → устойчивость → аннотация. Читатель не видит «воронку» отбора кандидатов.
3. **Перегруженные оси.** 15 боксов `caller × context` на одной оси (см. boxplot длины/дельты) — нечитаемо; подписи налезают друг на друга.
4. **Fixed-window callers искажают сравнение.** methylKit (тайлы 1000 п.н.) показывается в распределении длин как нулевой разброс (уже частично решено исключением в интерактивном отчёте, но в matplotlib-отчётах ещё нет).
5. **Нет UpSet-графиков.** Пересечения поддержки между callers (ключевой результат консенсуса) сейчас показываются грубым bar-ом комбинаций. Нужен полноценный UpSet.
6. **Несогласованная палитра и подписи.** Разные графики используют разные цвета для одних и тех же сущностей (контексты CG/CHG/CHH, направления hyper/hypo, статусы), нет единой цветовой схемы и единых человекочитаемых заголовков осей.
7. **Нет числа наблюдений.** Боксплоты не показывают `n` по группам, что критично, когда у каллера 5 регионов, а у другого 5000.

## 2. Целевой набор фигур, привязанный к этапам анализа

Фигуры должны рассказывать пайплайн по порядку. Минимальный обязательный набор:

| Этап | Фигура | Требование |
|------|--------|-----------|
| Вход | сводка покрытия/числа сайтов по контекстам | фасет по контексту |
| Вызов callers | число DMR по caller × context | сгруппированные бары с легендой-контекстом вне осей |
| Эффект | распределение \|delta\| (фасет по контексту), лог-шкала при большом разбросе | боксплот/виолин + `n` под группами; fixed-window callers помечены |
| Длина | распределение длин DMR | **исключить/пометить** fixed-window callers; фасет по контексту |
| **Консенсус** | **UpSet поддержки callers** (см. §3) | заменяет текущий bar комбинаций |
| Консенсус | чувствительность к порогу перекрытия τ | кривая `n регионов`(τ) с легендой серий вне осей |
| Консенсус | распределение финальных тиров по контекстам | stacked-bar, единая палитра тиров |
| Подтверждение | GLM vs GLMM scatter | hover/подпись `region_id`, раскраска по `GLMM_CONFIRMED/GLM_ONLY/...`, диагональ; легенда вне осей |
| Подтверждение | QQ-plot региональных p-значений comb-p (Brown) | демонстрация калибровки |
| Устойчивость | bootstrap CI «caterpillar» | подсветка CI∋0; легенда стабильности вне осей |
| Аннотация | gene/TE/GO overview, метаген-occupancy, projection-sensitivity, feature-class, TE-enrichment | единая палитра, легенды вне осей |
| Итог | «воронка»: всего кандидатов → консенсус ≥2 callers → подтверждённые GLMM → устойчивые | новая сводная фигура, отражающая отбор |

Фигура «воронки» (последняя строка) — **новая** и прямо закрывает претензию «графики не отражают процесс анализа».

## 3. UpSet-графики (UpSetR / ComplexUpset)

**Требование.** Пересечения поддержки DMR-callers визуализировать как UpSet-плот
(матрица пересечений + бары размеров), а не как длинный bar строковых комбинаций.

Вход: булевы колонки поддержки из консенсус-матрицы
(`*_support` из [build_caller_support_matrix](../python/src/bsx2/analysis/dmr_harmonization.py)),
либо поле `supporting_callers`.

Развилка реализации (решить при реализации):
- **R: `ComplexUpset` (предпочтительно) или `UpSetR`.** Соответствует тому, что
  R уже используется для callers; даёт публикационное качество и легко
  встраивается в `thesis_figures` как ещё одна PDF-фигура. Минус — ещё один
  R-вызов и зависимость от R-пакета.
- **Python: `upsetplot` (matplotlib).** Остаётся в Python-стеке отчётов; PNG
  затем встраивается в интерактивный отчёт как и прочие аннотационные фигуры.
  Минус — менее «публикационный» вид, чем ComplexUpset.

Требования к самому UpSet независимо от бэкенда:
- сортировка пересечений по размеру (degree/cardinality), показывать топ-N;
- разбиение по контексту (отдельные UpSet на CG/CHG/CHH либо фасет);
- аннотация размеров над барами;
- согласованная палитра callers с остальными фигурами.

---

## 4. Общие требования к оформлению (все бэкенды)

- **Легенда всегда присутствует** там, где есть >1 серии, и **вынесена за
  пределы области данных** (matplotlib: `bbox_to_anchor` справа/снизу + `ncol`;
  Plotly: `legend` вне `plot area`; никаких легенд поверх точек/боксов).
- **Единая палитра** для повторяющихся сущностей: контексты CG/CHG/CHH,
  направления hyper/hypo, статусы (`GLMM_CONFIRMED/GLM_ONLY/...`), тиры,
  matched/unmatched. Палитру вынести в один модуль-константу и переиспользовать
  во всех отчётах (сейчас цвета дублируются и расходятся).
- **Фасетирование** вместо нагромождения категорий на одной оси (по контексту
  и/или по каллеру).
- **`n` по группам** подписывается на боксплотах/барах.
- **Лог-шкала** для величин с большим разбросом (\|delta\|, длина) — автоматически
  при разбросе > 2 порядков (логика уже частично есть в caller_summary).
- **Доступность**: палитра, различимая при ч/б печати и для дальтоников
  (например, Okabe–Ito); тиры/статусы дополнительно различать порядком, а не
  только цветом.
- **Подписи осей человекочитаемые** (не `_abs_delta`, а «|Δ метилирования|»).
- **Согласованность статичного и интерактивного слоёв**: одинаковый набор и
  оформление фигур в `thesis_figures` (PDF) и в `interactive_report` (HTML).

---

## 5. Критерии приёмки

1. На каждой фигуре с >1 серии есть легенда, и она **не пересекается** с данными.
2. UpSet-плот поддержки callers построен (ComplexUpset/UpSetR или upsetplot) и
   заменяет bar строковых комбинаций в консенсус-секции.
3. Появилась сводная «воронка» отбора кандидатов.
4. Распределения длин не показывают fixed-window callers как нулевой разброс
   (исключены или явно помечены) во **всех** отчётах, включая matplotlib.
5. Единая палитра вынесена в общий модуль и применяется во всех отчётах.
6. Боксплоты подписаны числом наблюдений `n`.
7. Набор и оформление фигур согласованы между PDF-бандлом и интерактивным HTML.

## Статус реализации

Реализовано (общие модули переиспользуются статичным PDF-бандлом и интерактивным отчётом):
- Единая палитра и вынесенные за оси легенды — `reports/palette.py`, `reports/theme.py`.
- UpSet с цветом по каллерам (ComplexUpset, R) — `reports/upset_caller_support.{py,R}`.
- Тепловая карта согласованности callers (Jaccard) — `reports/concordance.py`.
- Воронка отбора кандидатов (трапеции в PDF, бары в интерактиве) — `reports/funnel.py`.
- Volcano (Δ vs −log10 q), фасет по контексту, цвет по каллеру — `interactive_report.py`, `thesis_figures.py`.
- Фасетинг |delta|/длины по контексту с подписью `n`, исключение fixed-window callers — `reports/caller_summary.py`.
- Genome-wide Manhattan-трек DMR по хромосомам, цвет по контексту — `reports/genome.py`.

Возможные дальнейшие улучшения (вне текущего объёма): караиотипные ленты с тиками TE/гены, интерактивные кросс-фильтры (Panel widgets), экспорт фигур в SVG.

## 6. Вне области этой задачи

- Изменение самой статистики/логики консенсуса (это другие задачи).
- Запуск новых callers.
- Добавление новых типов анализа; речь только о подаче уже вычисленных данных.
